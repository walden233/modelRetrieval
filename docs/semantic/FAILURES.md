# 语义检索失败案例分析

**历史协议说明：** 本报告记录已完成的20帧、S0–S5实验。当前实现已改为16帧、S1/S2c/S2w/S3/S4/S5，以下数值与案例不代表新协议结果；原脚本按旧组名读取产物，归档后需明确指向历史产物，不能直接用于新协议。

本报告基于当时已保存的 GLM-5.3-Flash、20 帧、S0–S5 联合标注及 BGE-M3 检索结果。主分析为 cfg2/test，补充 cfg3/test。没有重新调用标注 API，没有修改提示词、划分、向量、检索结果或原视频。

结论：失败至少涉及**提取错误、任务与执行阶段的差异、文本表达丢失区分信息、标签／表示引入的干扰，以及评价粒度与文本不可辨识性**。不能全部归结为语义模态的天然局限，也不能将所有错误都解释为大模型误识别。

## 1. 数据范围与证据边界

| 数据 | scene | 人类查询 | 机器人候选 | 覆盖 |
|---|---:|---:|---:|---|
| cfg2/test | 120 | 240 | 240 | 完整，480段视频 |
| cfg3/test | 128 | 256 | 256 | 完整，512段视频 |

两组的 `metrics.json` 均为 `partial=false`。六种表示均来自 `jobs/glm20-r3`。分析的是人类→机器人 Top1；task/scene 按现有 ID 定义，不临时修改正样本。

逐项读取原始排名与六组文本；另外对15个有针对性选择的scene、60段视频进行每段6帧的本地抽查，并保留台灯案例的原分辨率细节。精选10条查询记录为案例。它们是用于解释机制的目的性抽查，不是随机人工标注集，**不能据此报告各原因在全部失败中的百分比**。短时接触、成功状态和动作顺序仍可能需要逐帧确认；下文将确定的文字／排名事实与视觉解释分开。

## 3. 案例归因

以下短ID中的 `A=036422060215`，`B=037522062165`；特殊相机写全。Rank均为原始完整语义测试库中的第一个正样本排名，数值越小越好；跨模态共同库排名另列。

### C1/C2：机器人目标误识别，导致候选根本没有被正确描述

**cfg2/task_0020/scene_1/A/human**：人类S0为按台灯开关；两个同scene机器人视频的S0分别写成“抓住手持设备并调整位置”和“抓住桌布边缘”。六组task Rank为 `35/56/56/115/89/63`。S0 Top1是task_0021/scene_4/B的“机器人按台灯开关”，相似度0.8042，而同task的机器人已被错误表述。

[四段视频抽帧](../../artifacts/semantic/v2/failures/cases/cfg2_0020_1.jpg)中可以看到台灯及机器人末端靠近其底座；布面和末端遮挡增加了识别难度。这里可以确认对象／关注目标冲突，但不能仅用抽帧判定每次是否成功打开灯。

**cfg3/task_0036/scene_4/A/human**更明显：人类描述按亮台灯，机器人两视角却描述抓木块。六组task Rank为 `87/40/53/56/45/108`。[原分辨率细节](../../artifacts/semantic/v2/failures/cases/cfg3_lamp_detail.jpg)显示机器人末端接近台灯底座，[四视频上下文](../../artifacts/semantic/v2/failures/cases/cfg3_0036_4.jpg)也可对照。

**归因**：优先归入提取可靠性问题，尤其是机器人对象选择、遮挡和接触行为解释。不是“语义描述无论如何都无法表达这个任务”。两个机器人视角一致地说错，也说明文本一致性不能替代事实正确性。

### C3：完全相同的候选文本，无法用语义唯一定位scene

**cfg2/task_0017/scene_2/B/human**的S0是“拿起笔并放入杯子”。候选库中以下三个机器人视频的S0完全相同：

- task_0017/scene_2/A/robot；
- task_0017/scene_2/B/robot；
- task_0017/scene_3/104122061850/robot。

文字均为：`A robot arm picks up a pen from the table and places it into a cup.` 三个候选并列Top1，相似度0.8327；当前固定排序把另一scene排在前面，因此task Rank1、scene Rank2。

[scene2抽帧](../../artifacts/semantic/v2/failures/cases/cfg2_0017_2.jpg)、[scene3抽帧](../../artifacts/semantic/v2/failures/cases/cfg2_0017_3.jpg)。确定的是**编码输入完全相同**，所以相同文本编码器无法区分；这不意味着视频本身相同，也不意味着所有scene失败都由并列造成。

cfg2/S0共有4组机器人文本重复，涉及9段视频，其中1组跨scene、2组跨task；仅4个查询出现Top1并列。因此“文本碰撞”是可验证机制，但不足以解释总体差距。

**归因**：语义表示丢失实例特征，以及scene评价要求高于粗任务描述的区分能力。这是适合衔接视频／轨迹补充信息的案例；即使描述事实正确，也可能无法唯一定位实例。

### C4/C10：动作和对象相同，细粒度执行方式没有被充分区分

**cfg2/task_0043/scene_3/B/human**与task_0044/scene_4/B/robot都被概括为“旋转游戏方向盘”。S0把task44候选排在task43正样本之前，task Rank2；反向查询**task_0044/scene_4/A/human**同样把task43排在第一，task/scene均为Rank2。

[task43画面](../../artifacts/semantic/v2/failures/cases/cfg2_0043_3.jpg)、[task44画面](../../artifacts/semantic/v2/failures/cases/cfg2_0044_4.jpg)。画面中方向盘的姿态、操作位置、局部转动和整体重定位等细节有差别，而粗描述都保留“方向盘＋旋转”。要确定哪个相对运动变量真正区分task，需要进一步量化，不能凭task编号推断动作定义。

在严格共同候选库中，task44这条查询的S0 scene Rank2、视频E1 Rank2、轨迹T1 Rank1，提供了**实际存在的轨迹互补例子**。这不能证明轨迹编码器一定显式识别了上述某个物理变量。

**归因**：语义相近任务之间的细粒度动作／几何区分不足；同时要承认原有task标签并不保证自然语言类别完全可分。

### C5：粗标签不仅没补充细节，还可能加入错误属性

**cfg2/task_0005/scene_2/B/human**：S1明确描述推动木块；S2保留相同描述，附加标签却包含 `grasp, transport`。S1的task/scene均为Rank1，加标签后的S2降为Rank7；新的Top1是task_0004/scene_3/B/robot的抓取、抬起和放置木块。

[原视频抽帧](../../artifacts/semantic/v2/failures/cases/cfg2_0005_2.jpg)可见手接近木块，但仅靠6帧不估计推动幅度。**可以确定的是描述写push、标签写grasp，且附加标签后排名退化。** 标签并不是独立校验后的额外事实。

总体上，S1→S2在cfg2的task Top1修复18条、破坏15条，净增3；scene修复13条、破坏15条，净减2。cfg3/task修复14条、破坏21条，净减7；scene净减2。

**归因**：标签信息粒度粗、标签与描述不一致、通用动作标签容易让不同任务共享表示。样本中的相似度变化支持“附加标签改变了排序”，但不足以证明某个词在编码器中的单独因果效应。

### C6：同次生成不保证同一事实，不能把全部退化归因于格式

**cfg2/task_0088/scene_2/A/human**：S0写“沿板滑动金属环到支架旁”，S4改为“把环拿起，搬动，再放下”。S0 task Rank1，S4降至Rank171。这里不仅是对象／操作分段或去颜色，**动作事实也发生了变化**。

[抽帧](../../artifacts/semantic/v2/failures/cases/cfg2_0088_2.jpg)显示人类移动小金属物体，而同scene机器人描述与抽帧偏向悬停、未观察到完整搬移动作。瞬时动作可能被6帧漏掉，因此是否存在截取阶段／执行完成度问题仍需逐帧核查。

这条案例还提醒：S0恰好命中，并不证明它给出了最忠实、最完整的执行描述。较详细的文本可能揭示人机实际执行阶段的差异，进而降低按既有task/scene关联标签计算的相似度。

**归因**：表示间事实漂移；叠加人机可见行为／阶段不一致的可能性。不能直接写成“结构化文本一定弱于自然语言”或“长文本一定干扰检索”。

### C7：关键控制动作漏掉，鼠标键盘等无关活动占据描述

**cfg3/task_0016/scene_4/B/human**的S0/S1只描述鼠标和键盘；另一人类视角却描述按音箱控制。机器人文本又被写成末端在布面移动，没有一致识别音箱操作。[四段视频抽帧](../../artifacts/semantic/v2/failures/cases/cfg3_0016_4.jpg)中可见音箱、桌面活动以及机器人末端在相应区域移动。

B视角的六组task Rank为 `46/88/68/146/130/17`。对A视角，在共同库中S0/task Rank39，而视频E1/task Rank1，提供视频补充证据；B视角仍困难，说明不能用单个成功视角代表整个scene。

**归因**：关键动作遗漏、无关活动进入文本，以及视角造成的证据覆盖差异。不能仅凭抽帧区分遮挡、抽帧遗漏和原片段时段差异，也没有证据据此宣称原数据配对错误。

### C8：人机实际执行细节不同，详细表述放大跨域差异

**cfg2/task_0051/scene_1/B/human**被写成“将玩具飞机放到桌面并滑动”，机器人描述“从人手接过玩具车并放下”。S0 task/scene Rank1，S1降为Rank11；S1 Top1换成了另一task中机器人推动玩具车的片段。

[原帧](../../artifacts/semantic/v2/failures/cases/cfg2_0051_1.jpg)支持人类侧积木玩具与机器人侧小车／人机递交的细节差别。A视角还把桌面描述成倾斜板，提示表面与运动解释也可能有误。

**归因**：人机对象具体形态、交接和执行阶段差异，与可能的表述错误共同作用。合理的任务语义应保留有用动作关系，同时允许执行者和物体实现方式不同；不能强行要求两侧描述逐字一致，也不能简单将S0优势归因于句子更短。

### C9：视角相关的动作解释互相冲突

**cfg2/task_0037/scene_3**：人类A视角写“拿盖子并旋回瓶子”，B视角写“把滴管瓶移到杯子上并倒液体”；机器人描述又偏向靠近杯子或拿起小物体。[四视频抽帧](../../artifacts/semantic/v2/failures/cases/cfg2_0037_3.jpg)能看到杯子、小瓶和瓶盖，但不足以确认精细液体结果。

A查询六组task Rank为 `59/31/43/66/41/19`，全部未Top1。应先核查瓶盖／刷头的对象识别、旋转和倾倒的动作解释，不要直接用这个案例证明“轨迹必然比文本更好”。

**归因**：视角相关的动作解释错误与人机执行差异，当前证据不支持唯一主因。保留为待精查案例。

## 4. 视频和轨迹是否真的提供了补充信息

视频E1与语义测试集合完全一致；轨迹T1的现有评估集合较大且缺少部分当前语义测试视频，因此不能直接拼接其原排名。共同库为cfg2的234 query/234 candidate、cfg3的243/243。下表每行的分母都是**共同库上重新计算的S0失败数**，不是完整语义库中的87/134等。

## 5. 如何在论文中归因和组织

推荐将失败分析写成以下顺序：

1. **可靠性边界**：先展示台灯、音箱等提取错误。说明冻结VLM会受遮挡、机器人外形、关键帧覆盖和主体选择影响；语义标注不是事实真值。
2. **表示策略的代价**：标签可能提供粗任务线索，也会引入噪声；分离、泛化、JSON并不自动提升检索，且同次输出存在事实漂移。cfg2中S0→S4修复17个task查询、破坏48个；cfg3为26/44。只能归结为当前完整表示策略的结果，不能只归因于序列化格式或文本长度。
3. **语义本身的区分上限**：笔放杯子的完全相同文本、近义的方向盘任务，说明动作名词正确也可能缺少实例、相对运动和几何细节。此处再自然引出视频／轨迹。
4. **用共同集合上的真实互补统计收束**：使用上一节数据和一两个视频／轨迹命中的案例，指出补充信息的必要性，把实际融合收益留给系统章节。

可用于正文的表述：

> 失败既来源于视觉语言模型的任务提取误差，也来源于语言表述对实例与细粒度运动信息的压缩。细化或结构化描述并不必然提高匹配质量，因为增加的属性可能包含识别错误，且人机执行过程不一定具有相同的可见阶段。即使粗任务语义正确，相同或近义描述仍可能不足以区分不同执行实例。在严格对齐的共同候选集合上，部分语义失败可由视频或轨迹检索命中，表明几何与视觉信息具有补充价值。

不宜写成：全部失败都是语言丢失细节；结构化一定更准确；更长一定更差；多视角描述一致就一定正确；另一模态命中就等于融合收益；同task必然应该拥有完全一致的动作描述。

面向scene教师：C1/C2/C7/C9提示先处理主体、对象和动作冲突，不要把四段文本硬合成一个“标准答案”。现有汇总允许无可靠共享动作时返回null，应保留该机制；两个机器人视角一致错误也不能靠多数票证明正确。教师汇总不能反写单视频描述后再用于本章独立检索，否则会引入配对信息。
