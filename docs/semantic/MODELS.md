### 版本与 Batch 的重要区别

Qwen3.7-Plus 官方文档中，别名 `qwen3.7-plus` 标注支持批量推理，并列出 Batch File 输入 1／输出 4 元每百万 token 的单价，即在线 2／8 的半价；固定快照 `qwen3.7-plus-2026-05-26` 的能力表标注批量推理不支持，快照价格表也没有 Batch 行。

因此推荐固定快照的预算按 **在线 2/8** 计算，不预先承诺 Batch 半价。若实际控制台确认某个固定版本支持 Batch，再重新核算。为了本规模几十元的差额改用会更新的别名，不是优先选择。

Kimi 官方模型列表说明 `kimi-k2.5` 已于 2026-08-31 下线，不能再按早期 K2.5 的价格和能力选型。新模型名和端点必须以当前官方列表为准。

当前子集每个 scene 有三组人机相机视频。若每 scene 只使用一组相机，共 1,380 段；两组共 2,760 段；全部三组共 4,140 段。此前 218 个 cfg2 scene 的旧标注不代表全量覆盖。

一次调用共同生成标签、普通描述、对象/操作描述、动作优先描述与操作 JSON，只需每视频一次。五种表示会增加输出长度，但不把视觉输入重复收费五次。

### 统一计价场景

暂按每视频 **输入 5,000 token、计费输出合计 2,000 token** 计算。输入包含图像与 prompt；输出预算须包含相应模型计费的推理和正文，不含重试、额外缓存写入与文件存储等费用。GLM-5.3-Flash 不能关闭思考，这一输出用量假设需要小规模真实 usage 校准。

这是预算假设，不是付费调用实测。不同模型对同一帧数的视觉 token 消耗不同，须用开发集返回的 usage 校准。

```text
单视频费用 = (输入 token × 输入单价 + 输出 token × 输出单价) / 1,000,000
总费用 = 视频数量 × 单视频费用
```

| 模型 | 单视频估算 | cfg2 全量 | cfg3 全量 | 4,140 段合计 |
|---|---:|---:|---:|---:|
| Qwen3.7-Plus | 0.026 元 | 67.70 元 | 39.94 元 | **107.64 元** |
| Qwen3.5-Plus | 0.0136 元 | 35.41 元 | 20.89 元 | 56.30 元 |
| Qwen3.8-Max | 0.132 元 | 343.73 元 | 202.75 元 | 546.48 元 |
| GLM-4.6V | 0.011 元 | 28.64 元 | 16.90 元 | **45.54 元** |
| GLM-5.3-Flash | 0.0096 元 | 25.00 元 | 14.75 元 | 39.74 元 |
| GLM-5.3-FlashX | 0.024 元 | 62.50 元 | 36.86 元 | 99.36 元 |
| Doubao-Seed-2.1-Lite | 0.0094 元 | 24.48 元 | 14.44 元 | 38.92 元 |
| Doubao-Seed-2.1-Pro | 0.09 元 | 234.36 元 | 138.24 元 | 372.60 元 |
| Kimi K2.6 | 0.0865 元 | 225.25 元 | 132.86 元 | 358.11 元 |

### 输入尺寸与时长抽查

每 cfg 按文件排序等间隔选 16 段，读取视频元数据，不解码全部数据。32 段均为 640×360：

| 抽查 | 最短 | 时长中位数 | 最长 |
|---|---:|---:|---:|
| cfg2，16 段 | 2.28 秒 | 10.48 秒 | 53.48 秒 |
| cfg3，16 段 | 1.32 秒 | 5.88 秒 | 64.32 秒 |

这些是抽查值，不是全库统计。Qwen 官方图像估算按缩放后的 32×32 像素块计 token；640×360 级别每帧约数百 token，16 帧加提示后以 5K 输入作起始预算有依据，但应以 usage 为准。不能上采样并期待恢复原视频中没有的小物体细节。

## 4. 当前输入与“原生视频”的区别

当前 [scanner](../../src/bise/data/rh20t/scanner.py)通过 `linspace` 均匀取 16 帧；[请求组装](../../src/bise/modalities/semantic/vlm_client.py)将每帧编码成 JPEG/Base64，以多个 `image_url` 输入。没有发送 MP4，也没有逐帧显式时间戳。

应区分三层：

1. 模型是否经过视频/时序相关训练。
2. API 是否接受视频文件、URL 或预抽帧视频序列。
3. 实际送入视觉编码器的帧、分辨率、时间位置和压缩方式。

“API 接受 MP4”不表示逐帧读取全部原始视频信息，也不保证比固定抽帧更好。视频专用位置处理和时间压缩可能不同于独立图片输入，不能把两种请求当成完全等价。

| 厂商 | 官方输入方式与处理说明 |
|---|---|
| 阿里云 | 支持多图、视频文件/URL及预抽帧图像列表。文档明确视频文件先抽帧再计 token，视频路径还涉及时间压缩与帧数策略 |
| 智谱 | GLM-4.6V 支持视频、图像等；现有项目只接入多图输入。是否采用原生视频需适配请求并验证采样参数 |
| 火山方舟 | 支持视频 URL、File ID 等；可设置 fps，当前视频教程默认每秒一帧。上传文件时也可指定预处理 fps |
| Kimi | 支持上传视频并通过 `ms://file-id` 引用；官方明确视频由若干关键帧组成，可用 token 估算接口预估输入 |
| 腾讯 | 提供视频生文模型与专门视频请求，需遵循该接口的输入格式 |

依据：[阿里云视频与 token 计算](https://help.aliyun.com/zh/model-studio/vision/)、[火山视频理解](https://docs.volcengine.com/docs/ark/video-understanding?lang=en)、[Kimi 视觉输入](https://platform.kimi.com/docs/guide/use-kimi-vision-model)、[腾讯对话 API](https://cloud.tencent.com/document/product/1729/105701)。

阿里云文档的示例视频 token 估算含 `ceil(num_frames/2)`，多图输入则逐图计数，说明视频封装与多图输入可能在计费和时间处理上不同。该公式不能推广到所有厂商，也不能未经校准当成所有新版本的精确成本公式。

## 5. 主实验输入建议

主实验继续本地固定抽帧，优先保证五种表示和跨厂商对照看到同样的视觉证据：

- 主实验每视频均匀16帧，按时间顺序，覆盖开始和结束；成本实验独立均匀取 32／16／8 帧，厂商对比固定 16 帧。
- 记录实际帧索引与时间；请求中提供序号和真实时间戳。
- 固定图像尺寸策略，保持原始可见信息，不做针对 task 的裁剪规则。
- 五种表示一次生成，温度等参数按厂商支持情况配置，不生搬现有 GLM 请求参数。
- 关闭联网、工具与多轮 agent 调用，控制实验输入来源。
- 使用模型支持的结构化输出模式，仍做本地 schema 和事实一致性检查。
- 保留返回的模型标识、usage、推理 token、提示版本与输入协议，作为实验元信息，不新增数据哈希。

如果阿里云选定快照的预抽帧视频序列接口验证可用，可以保留本地选帧、改用视频序列封装，但这应是明确、固定的输入协议，不能与其他模型的独立多图输入混在同一个单因素比较中。

原生视频输入仅作为可选的本地协议检查，不是当前章节必做实验。若后续确需检查，可在相同小样本上比较：

1. 固定主协议的16帧多图＋时间戳。
2. 同模型视频接口，显式固定 fps/分辨率，记录实际 token；能控制同帧时优先同帧比较。

若视频接口用了更多帧，结果反映“输入策略整体变化”，不能把收益全归因于“原生视频”。出现稳定的动作顺序或短事件收益后再决定是否替换主协议，避免全量重跑多套输入。

## 6. 现有代码接入注意点

- 当前 `thinking={type:...}` 是 GLM 风格，Qwen 应按 `enable_thinking` 等官方接口参数处理。更换 base_url/model_name 不足以保证请求完全兼容。
- 当前 Batch 客户端针对智谱 SDK；阿里云即使有 Batch 支持，也不能直接复用智谱 job 接口。固定快照暂按在线请求实现预算。
- 当前帧函数只返回图像，新增显式时间信息需要返回或另外记录索引/FPS/时间戳。
- 六组共享一次VLM调用。S2c拼接S1描述与标签编码，S2w分别编码后按0.7:0.3融合归一化；S5只编码structured子对象。
- 新模型或新提示必须使用独立版本；已有 completed/raw 响应的跳过机制不能被误认为已重新标注。

## 7. 最小执行方案

1. 实现 GLM-5.3-Flash 的一次输出五种表示，用小规模视频检查完整链路；这一步不进论文实验。
2. 固定 prompt、schema 和输入协议，cfg2/cfg3 全量每视频调用一次，比较五种表示的检索性能。
3. 固定 cfg2完整清单的60-task／60-scene／240-video子集，分别做 16 帧厂商对比和 32／16／8 帧对比；两条成本轴共用GLM16；相同完整协议可复用当前主实验16帧响应，缓存读取不算新API时延，旧20帧响应不能复用，不做完整交叉矩阵。
4. 复用全量标注分析跨相机一致性，作为视频章节语义弱监督的依据。
5. 分析提取错误、语义信息局限，以及视频和轨迹的互补机会；不另设训练或迁移实验。

本轮完成的是官方资料调研、数据数量扫描与元数据抽查。厂商质量差异留给成本子集实测，表中费用是可复算预算场景，不是已经产生的账单。
