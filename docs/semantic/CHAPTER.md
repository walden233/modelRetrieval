# 语义检索章节方案

更新：2026-10-14。本文固化讨论后确定的实验范围；此前调研中的冲突建议以本文为准。这是后续实现与写作依据，不表示新标注流水线已完成。

## 1. 章节定位与边界

本课题根据人类提供的视频、轨迹或文本，从机器人候选库中检索对应执行。本章研究**视频任务信息如何组织成适合人机检索的语义表示**，篇幅约 10–12 页，使用冻结的视觉语言模型和文本编码器，不训练语义模型。

章节顺序确定为：**五种表示全量对比 → 成本与效率实验 → 跨视角一致性 → 失败与信息局限分析**。方法保持通用，不按当前 task 编写专用提示、答案词典或对象映射规则。cfg2、cfg3 是两个评估数据配置，本章不设置训练后迁移协议，也不将 cfg3 结果称为迁移实验。

文本输入有两个来源：用户直接描述任务，以及从用户视频提取任务信息。两者共用表示与机器人候选库，但前者是请求、后者是观测，信息完整程度不同。当前主实验围绕视频提取语义展开，不另加一套大规模人工文本查询实验。

## 2. 主实验：同一次提取，比较五种表示

主模型确定采用 **GLM-5.3-Flash**。cfg2、cfg3 中每个人类视频和机器人视频、每个相机分别标注；**每视频一次调用，同一个 prompt 同时生成五种表示所需的信息**，不分别调用五次。

| 编号 | 表示 | 内容与组织方式 | 比较目的 |
|---|---|---|---|
| S1 | 普通描述 | 自然语言描述视频，不刻意排除操作对象等可见信息 | 基础语义检索能力 |
| S2 | 描述＋标签 | 原样复用 S1 描述，加上同次输出的标签 | 标签是否补充区分信息，还是引入粗粒度干扰 |
| S3 | 操作与对象分离 | 分别表达操作和对象，保留动作与对象、来源与目标的对应关系；可加入可见结果 | 显式区分操作和对象是否有帮助 |
| S4 | 动作优先的分离描述 | 仍区分操作和对象，但突出操作行为，弱化对象的外观与类别细节 | 减少对象外观依赖是否改善人机匹配 |
| S5 | 原始语义结构 JSON | 直接序列化模型输出的语义结构子对象，保留对象、操作及可见结果 | 结构本身是否比自然语言组织更适合检索 |

S3、S4、S5 均由模型在同一次响应中直接输出，**不改成先提取一份事实、再用本地模板拼出三个版本**。这是表示策略比较，同时涉及信息取舍和组织方式，不宣称每一组都是严格的单因素消融。

以下仅示意响应分区，字段细节留待实现时确定：

```json
{
  "description": "普通描述",
  "labels": {},
  "object_action_text": "操作与对象分离的描述",
  "action_focus_text": "动作优先的描述",
  "structured": {
    "objects": [],
    "operations": [],
    "result": null
  }
}
```

实现时需遵守：

- S2 的描述与 S1 完全相同；标签的拼接或向量融合方式在全量实验前固定，不同时修改描述内容。
- S3 不能退化为互不关联的名词、动词列表。S4 建议保留必要对象角色，例如“源容器→目标容器”，而非只剩通用动词；具体弱化规则在实现前固定。
- S5 编码 `structured` 子对象，不把整个响应、其他四种表示、task ID、路径或配对信息一起编码。JSON 序列化固定，操作数组保持时间顺序；不是另行渲染成有序散文。
- 五种表示均基于可见证据，结果不可见则留空。标签可采用受控类别，但不能让粗标签词表限制描述中的具体操作。
- 人类查询与机器人候选独立标注，不能共用配对答案或同 scene 的标准描述。同次提取只指同一个视频的五种表示。
- 一次调用可以控制输入证据，但不保证五个输出事实完全一致；本地检查需覆盖动作遗漏、对象角色冲突和结果幻觉。

## 3. 本地检查、全量标注与检索评估

先写好代码，用小规模视频检查 API、抽帧、schema、解析、五种表示一致性、文本编码和完整检索链路。**这一步是工程可行性检查，不作为论文独立实验，也不设置正式的验证集选优流程。** 可行后固定 prompt、schema、输入协议及评估规则，再做全量对比。

输入继续采用本地抽帧，不要求改成原生视频接口。建议主实验按时间顺序均匀取 16 帧、覆盖首尾，记录帧索引与真实时间戳，并固定尺寸策略。原生视频输入不是本章必做实验。

| cfg3 | 64 | 256 | 768 | 768 | 1,536 |
| 合计 | — | 690 | 2,070 | 2,070 | **4,140** |

主实验统一文本编码器、符合该编码器规范的池化和归一化、查询与候选集合、正样本规则及指标；以人类→机器人为主，task 与 scene 粒度分别报告。**全量标注不等于无条件把所有视频作为测试候选**，评估所用划分和相机范围必须明确且在五组之间一致。

直接报告五种表示的全量检索表现，说明哪个在相应数据和指标下最好；若指标或 cfg2/cfg3 排名不同，如实保留。不能看过正式结果后反复改 prompt 再把最优版本称为原定实验。

五种表示共用一次标注调用，不分别比较五份 VLM 标注成本。文本长度、编码耗时可以记录，但与后续厂商、帧数实验中的标注费用区分。池化实现应规范，暂不再扩展一套大型文本编码器、重排序或复杂匹配实验矩阵。

## 4. 成本与效率：固定子集上的辅助实验

这部分比较检索质量、费用和速度，不重新标注全部数据，也不做厂商×帧数的完整组合。

| 实验 | 改变项 | 固定项 | 主要记录 |
|---|---|---|---|
| 厂商／模型对比 | 少量国内厂商模型 | 同一视频子集、帧数、prompt、完整输出要求、文本编码与评估 | 检索指标、实际费用、延迟、吞吐、成功率 |
| 输入帧数对比 | 建议 4／8／16 帧 | GLM-5.3-Flash、同一子集及其余协议 | 质量随输入成本与速度的变化 |

子集按 scene 采样，保留该 scene 的人类、机器人和全部相机，覆盖 cfg2/cfg3、不同任务和时长。建议约 24 个 scene、144 段视频作为起点；**最终规模、对照厂商和具体汇总指标尚待实现前确定**。主模型、主帧数对应的已有标注复用。

各模型必须生成同样完整的字段，不能少输出几个表示来获得更低费用或更快速度。记录实际 usage 与费用、延迟中位数/P95、固定并发吞吐，以及成功率、重试率、schema 合格率。不用未经解释的综合“性价比分数”代替原始结果。

成本子集中的结果可按同一规则报告五种表示，并对主实验表现较好的表示重点讨论；不按每个模型另选一个最有利表示后直接横比。本地可行性小样本与这里的正式成本子集用途不同。

预算和厂商资料见 [MODELS.md](MODELS.md)。其中价格为调研时点信息，预算是假设 token 用量下的估算，正式结果以实际调用记录为准。

## 5. 跨视角一致性及与视频章节的衔接

一致性分析放在本章，复用全量语义标注，不再额外全量调用模型。它回答：同一执行从不同相机观察，语义是否稳定且仍有区分度？

- 首先比较同一 scene、同一执行的不同相机：人类域内部、机器人域内部分别统计。
- 人类↔机器人另列为跨域分析；同 task 不同 scene 作为参考，不能要求其细节描述完全相同。
- 同时检查文本相似度、与负样本的区分，以及动作、对象角色、目标、结果的一致和缺失情况。只看正样本相似度不足以判断可靠性：泛化空话或共同错误也会一致。

这部分为第四章的语义弱监督提供可靠性与边界证据。第四章引用分析，说明教师信号如何构建、如何进入损失以及训练效果，不重复本章整套实验。检索最好的表示不自动等于最好的监督信号。

视频章节仍按此前确定的两条尝试推进：扩展模态内一致性；扩展模态内一致性＋语义监督。范围见 [视频跨相机方案](../video/CROSS_VIEW.md)。

## 6. 失败分析：落到语义信息局限与互补需求

失败案例需要分清原因，不能把所有错误统称为“语义不够”：

| 原因 | 典型情况 | 分析方向 |
|---|---|---|
| 提取错误 | 误认对象、漏掉动作、编造结果 | 标注可靠性问题，不能仅靠融合掩盖 |
| 语言表达丢失细节 | 路径、方向、幅度、速度、抓取方式或手形被概括 | 轨迹可提供运动与几何；视频可提供局部外观、空间配置等证据 |
| 查询本身不足以唯一定位 | 同一任务描述对应多个合理执行 | 检查多正样本与评价粒度，避免把合理候选算作纯语义失败 |

尽量对同一查询、同一候选库复用已有视频和轨迹结果，展示“语义失败但另一模态命中”以及“三者均失败”的案例。前者说明互补机会，不等于已证明融合收益；实际融合结论留给系统章节。由人类视频提取的文本与原视频相关，也不能当作三个完全独立的信息源。

## 8. 后续实现顺序与记录

按“响应 schema／prompt → 单视频解析 → 五种表示编码 → 小规模端到端检查 → 全量标注 → 主实验 → 成本子集 → 一致性与失败分析”实施。

保留原始响应、解析结果、模型与提示版本、抽帧参数、usage、错误和重试记录，以及检索排名和绘图原始数据。共享数据和标注尽量复用，不为每种表示复制一套视频清单，不往数据清单新增哈希。
