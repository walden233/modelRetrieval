# 语义检索章节方案

更新：2026-10-17。本文固化讨论后确定的实验范围；此前调研中的冲突建议以本文为准。当前实现为schema_version=3，16帧、六组共享提取、任务内容输出和集中存储。旧20帧实验已运行；本次新协议尚未付费标注。实际入口与存储见 [实现方案](PLAN.md)。

## 1. 章节定位与边界

本课题根据人类提供的视频、轨迹或文本，从机器人候选库中检索对应执行。本章研究**视频任务信息如何组织成适合人机检索的语义表示**，篇幅约 10–12 页，使用冻结的视觉语言模型和文本编码器，不训练语义模型。

章节顺序确定为：**简述基线、两种标签编码与其余表示的全量对比 → 成本与效率实验 → 跨视角一致性 → 失败与信息局限分析**。方法保持通用，不按当前 task 编写专用提示、答案词典或对象映射规则。cfg2、cfg3 是两个评估数据配置，本章不设置训练后迁移协议，也不将 cfg3 结果称为迁移实验。

文本输入有两个来源：用户直接描述任务，以及从用户视频提取任务信息。两者共用表示与机器人候选库，但前者是请求、后者是观测，信息完整程度不同。当前主实验围绕视频提取语义展开，不另加一套大规模人工文本查询实验。

## 2. 主实验：S1、S2c、S2w、S3、S4、S5

主模型确定采用 **GLM-5.3-Flash**，主实验均匀采样 **16 帧**。当前完整标注范围初始导入 s44 的 cfg2/cfg3 `split_manifest_video.json`，之后冻结于 `artifacts/semantic/v2/scope.json`，不再绑定 batch，保留完整来源快照；当前标注其中cfg2完整清单及cfg3清单全部视频，不额外加入清单外相机。人类和机器人视频分别标注；**每视频一次调用，共用 prompt 主体并按角色切换关注主体指令，同时生成六种表示所需的信息**，不分别调用六次。保留显式增量标注入口。

人类视频关注主要演示者；机器人视频关注机器人及其操作对象，忽略旁观人类。仅在真实人机交互时保留人类参与，并正确归属各主体的动作，不把人类动作写成机器人动作。

| 编号 | 表示 | 内容与组织方式 | 比较目的 |
|---|---|---|---|
| S1 | 简洁自然描述 | 合并原S0/S1；1–2句描述相关对象、主要动作和可见结果；保留必要外观，省略无用颜色、背景、衣着和偶然动作 | 基础语义检索能力 |
| S2c | 描述＋标签，拼接编码 | 同次S1原文＋四维标签，拼成一个文本编码 | 粗标签能否补充描述，或引入噪声 |
| S2w | 描述＋标签，分别编码 | 同一份描述、标签分别归一化编码，按0.7:0.3加权后归一化 | 显式控制标签权重是否优于拼接 |
| S3 | 操作与对象分离 | 分别表达操作和对象及其关系，可加入可见结果；忽略无用颜色 | 显式区分操作和对象是否有帮助 |
| S4 | 功能角色与操作过程 | 功能角色替代具体对象名称，保留操作机制及源／目标关系，与S3使用相同动作、顺序和结果 | 功能抽象能否减少人机对象差异并保留任务区分度 |
| S5 | 原始语义结构 JSON | 直接序列化模型输出的语义结构子对象，保留对象、操作及可见结果 | 结构本身是否比自然语言组织更适合检索 |

S3、S4、S5 均由模型在同一次响应中直接输出，**不改成先提取一份事实、再用本地模板拼出三个版本**。这是表示策略比较，同时涉及信息取舍和组织方式，不宣称每一组都是严格的单因素消融。

联合响应只含以下任务内容，不含理由、不确定性说明、可见性、置信度或证据：

```json
{
  "description": "1–2句自然简述，不附加标签",
  "labels": {},
  "object_action_text": "操作与对象分离的描述",
  "action_focus_text": "动作优先的描述",
  "structured": {
    "objects": [],
    "operations": [],
    "result": null
  }
}
```

实现时需遵守：

- 标签在labels字段单独输出，不混入S1。S2c/S2w复用完全相同的描述和四维标签（能力、复杂度、环境、场景类别），不采用新属性标签。两者仅改变编码组织；S2w融合向量，不融合检索分数。
- S3/S5提取规则保持原样；S4改为功能角色抽象。各组独立存储，不依赖S1目录。
- S3保留具体对象与操作关系；S4默认使用功能角色，仅为明确操作机制保留必要类别或结构，保持与S3相同的动作、顺序和结果，不额外添加接近、撤手、抓取或放置，也不把不同任务泛化成通用物体移动。
- S3/S4 都忽略与操作无关的物体、衣着和背景颜色；颜色确实用于区分交互对象／目标或表达可见状态变化时，保留最低必要信息，不一律删掉。
- S5 编码 `structured` 子对象，不把整个响应、其他五种表示、task ID、路径或配对信息一起编码。JSON 序列化固定，操作数组保持时间顺序；不是另行渲染成有序散文。
- 六种表示均基于可见证据，结果不可见则留空。粗标签允许未知，不推断不可见力、精度或操作成功；词表不限制其他表示中的具体操作。
- 人类查询与机器人候选独立标注，不能共用配对答案或同 scene 的标准描述。同次提取只指同一个视频的六种表示。
- 一次调用可以控制输入证据，但不保证六个输出事实完全一致；本地检查需覆盖动作遗漏、对象角色冲突和结果幻觉。

## 3. 本地检查、全量标注与检索评估

先写好代码，用小规模视频检查 API、抽帧、schema、解析、六种表示一致性、文本编码和完整检索链路。**这一步是工程可行性检查，不作为论文独立实验，也不设置正式的验证集选优流程。** 可行后固定 prompt、schema、输入协议及评估规则，再做全量对比。

输入继续采用本地抽帧，不要求改成原生视频接口。主实验按时间顺序均匀取 **16 帧**、覆盖首尾，记录帧索引与真实时间戳，并固定尺寸策略。原生视频输入不是本章必做实验。

2026-10-14 扫描的数据目录总量为 cfg2 2,604 段、cfg3 1,536 段，共 4,140 段；该总量不再作为当前默认标注范围。2026-10-17核查冻结来源快照如下；2026-10-18将其确认为当前完整标注范围：

| 数据 | task | scene | 人类视频 | 机器人视频 | 合计 |
|---|---:|---:|---:|---:|---:|
| s44 / cfg2 | 109 | 428 | 856 | 856 | 1,712 |
| s44 / cfg3 | 64 | 128 | 256 | 256 | 512 |
| 合计 | — | 556 | 1,112 | 1,112 | **2,224** |

当前默认标注cfg2的1712段（428个scene）与cfg3的512段（128个scene），共2224段。主表以cfg2完整清单的task检索为主体：109个task、856个query、856个候选；scene指标仍保存。cfg3沿用其test清单。评估严格限于list出现的视频，不将数据目录的其他相机或scene加进来。

s43、s44、s45出现的视频集合一致，但cfg2的train/val/test分配不同。当前语义独立保存最初导入的划分快照；所有活动产物集中在 artifacts/semantic/v2，旧格式仅归档。

主实验统一文本编码器、符合该编码器规范的池化和归一化、查询与候选集合、正样本规则及指标；以人类→机器人为主，task 与 scene 粒度分别报告。**全量标注不等于无条件把所有视频作为测试候选**，评估所用划分和相机范围必须明确且在六组之间一致。

直接报告六种表示的全量检索表现，说明哪个在相应数据和指标下最好；若指标或 cfg2/cfg3 排名不同，如实保留。不能看过正式结果后反复改 prompt 再把最优版本称为原定实验。

六种表示共用一次标注调用，不分别比较六份 VLM 标注成本。文本长度、编码耗时可以记录，但与后续厂商、帧数实验中的标注费用区分。池化实现应规范，暂不再扩展一套大型文本编码器、重排序或复杂匹配实验矩阵。

## 4. 成本与效率：固定子集上的辅助实验

这部分比较检索质量、费用和速度，不重新标注全部数据，也不做厂商×帧数的完整组合。

| 实验 | 改变项 | 固定项 | 主要记录 |
|---|---|---|---|
| 厂商／模型对比 | 少量国内厂商模型 | 同一视频子集、16 帧、角色关注规则、完整输出要求、文本编码与评估 | 检索指标、实际费用、延迟、吞吐、成功率 |
| 输入帧数对比 | **32／16／8 帧** | GLM-5.3-Flash、同一子集及其余协议 | 质量随输入成本与速度的变化 |

成本子集从cfg2完整冻结清单固定抽取 **60个不同task，每task一个scene，共240段视频**，保留清单中的两个相机及人机两侧，seed=44。对应人→机为120个query、120个候选。

每 task 一个 scene 会使成本子集的 task／scene 正样本相同，报告一套指标并说明；全量主实验仍区分两个粒度。主实验当前同为16帧，相同视频和完整协议可复用GLM16标注；成本两条轴也共用GLM16。缓存读取不计作新API延迟，需要独立实测时使用fresh-benchmark；旧20帧缓存不能复用。对照厂商及计时细节见 [实现方案](PLAN.md)。

各模型必须生成同样完整的字段，不能少输出几个表示来获得更低费用或更快速度。记录实际 usage 与费用、延迟中位数/P95、固定并发吞吐，以及成功率、重试率、schema 合格率。不用未经解释的综合“性价比分数”代替原始结果。

成本子集中的结果可按同一规则报告六种表示，并对主实验表现较好的表示重点讨论；不按每个模型另选一个最有利表示后直接横比。本地可行性小样本与这里的正式成本子集用途不同。

预算和厂商资料见 [MODELS.md](MODELS.md)。其中价格为调研时点信息，预算是假设 token 用量下的估算，正式结果以实际调用记录为准。

## 5. 跨视角一致性及与视频章节的衔接

一致性分析放在本章，复用全量语义标注，不再额外全量调用模型。它回答：同一执行从不同相机观察，语义是否稳定且仍有区分度？

- 首先比较同一 scene、同一执行的不同相机：人类域内部、机器人域内部分别统计。
- 人类↔机器人另列为跨域分析；同 task 不同 scene 作为参考，不能要求其细节描述完全相同。
- 同时检查文本相似度、与负样本的区分，以及动作、对象角色、目标、结果的一致和缺失情况。只看正样本相似度不足以判断可靠性：泛化空话或共同错误也会一致。

这部分为第四章的语义弱监督提供可靠性与边界证据。第四章引用分析，说明教师信号如何构建、如何进入损失以及训练效果，不重复本章整套实验。检索最好的表示不自动等于最好的监督信号。

scene 教师接口已实现：通过 --source 选定一种 S 表示，默认 S5，只读取该 scene 四段视频在该组的独立任务文本，文本模型只返回共享任务描述或 null，程序记录来源和可用标记。默认汇总当前标注范围的教师池，指定run时按其实际train导出；cfg2训练教师只使用对应run的train scene，失败标注需先补齐，不能借用val/test教师；不同来源的教师独立保存，已生成的教师保留来源记录。当前每 scene 是四段视频；不把六种表示当六份证据，也不自动加入第三相机。共享教师不用于本章独立语义检索或跨视角一致性统计。

视频章节仍按此前确定的两条尝试推进：扩展模态内一致性；扩展模态内一致性＋语义监督。范围见 [视频跨相机方案](../video/CROSS_VIEW.md)。

## 6. 失败分析：落到语义信息局限与互补需求

历史20帧协议的案例、客观计数和严格共同库互补统计见 [失败案例实证分析](FAILURES.md)。

失败案例需要分清原因，不能把所有错误统称为“语义不够”：

| 原因 | 典型情况 | 分析方向 |
|---|---|---|
| 提取错误 | 误认对象、漏掉动作、编造结果 | 标注可靠性问题，不能仅靠融合掩盖 |
| 语言表达丢失细节 | 路径、方向、幅度、速度、抓取方式或手形被概括 | 轨迹可提供运动与几何；视频可提供局部外观、空间配置等证据 |
| 查询本身不足以唯一定位 | 同一任务描述对应多个合理执行 | 检查多正样本与评价粒度，避免把合理候选算作纯语义失败 |

尽量对同一查询、同一候选库复用已有视频和轨迹结果，展示“语义失败但另一模态命中”以及“三者均失败”的案例。前者说明互补机会，不等于已证明融合收益；实际融合结论留给系统章节。由人类视频提取的文本与原视频相关，也不能当作三个完全独立的信息源。

## 8. 后续实现顺序与记录

按“响应 schema／prompt → 单视频解析 → 六种表示编码 → 小规模端到端检查 → 全量标注 → 主实验 → 成本子集 → 一致性与失败分析”实施。

保留原始响应、解析结果、模型与提示版本、抽帧参数、usage、错误和重试记录，以及检索排名和绘图原始数据。共享数据和标注尽量复用，不为每种表示复制一套视频清单，不往数据清单新增哈希。
